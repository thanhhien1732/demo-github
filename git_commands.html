4 Khu Vực Hoạt Động Của Git

Hiểu rõ cách dữ liệu di chuyển giữa các vùng lưu trữ

Working Dir → Staging → Local Repo → Remote
1

Working Directory

Thư mục làm việc trên máy tính bạn đang sửa mã nguồn (Untracked / Modified files).

→ Dùng git add chuyển sang Stage 2
2

Staging Area (Index)

Vùng chuẩn bị để gom các thay đổi trước khi đóng gói thành 1 commit chính thức.

→ Dùng git commit đóng gói vào Stage 3
3

Local Repository

Kho lưu trữ cục bộ (.git) đã lưu trữ đầy đủ lịch sử commit và các branch trên máy.

→ Dùng git push đẩy lên Stage 4
4

Remote Repository

Kho lưu trữ trên máy chủ đám mây (GitHub, GitLab, Bitbucket) để chia sẻ cùng team.

← Dùng git pull / fetch lấy về máy

Danh mục lệnh Đang hiển thị: 0 lệnh

Khởi tạo Bắt buộc khi bắt đầu

git init

Khởi tạo một Git repository trống ngay tại thư mục hiện tại. Git sẽ tạo ra thư mục ẩn .git chứa toàn bộ metadata và cơ sở dữ liệu.

git init
💡 Mẹo: Chỉ cần chạy 1 lần duy nhất khi tạo dự án mới.
Khởi tạo Kéo dự án có sẵn

git clone

Sao chép toàn bộ một kho mã nguồn từ GitHub hoặc remote server về máy tính cục bộ, bao gồm tất cả commit history và branch.

git clone <repo-url>
💡 Mẹo: Thêm tên thư mục ở cuối nếu muốn đổi tên thư mục tải về: git clone <url> my-folder
Cấu hình Thông tin tác giả

git config

Thiết lập thông tin tên và email của bạn. Git sẽ gắn nhãn này vào từng commit để mọi người trong nhóm biết ai đã viết code.

git config --global user.name "Tên"
💡 Mẹo: Dùng git config --list để xem lại toàn bộ cấu hình máy.
Cơ bản Dùng nhiều nhất ⭐

git status

Xem trạng thái các tệp tin trong Working Directory và Staging Area: file nào chưa được theo dõi (Untracked), file nào đã sửa, file nào sẵn sàng commit.

git status
💡 Mẹo: Dùng git status -s để xem dạng thu gọn (short format) dễ nhìn hơn.
Cơ bản Stage thay đổi

git add

Đưa các file đã sửa đổi từ Working Directory vào Staging Area để chuẩn bị đóng gói vào lần commit tiếp theo.

git add .
💡 Mẹo: Dấu chấm . là thêm tất cả thay đổi, hoặc chỉ định tên file: git add app.js
Cơ bản Tạo snapshot

git commit

Lưu lại toàn bộ nội dung trong Staging Area thành 1 phiên bản chính thức (commit) đi kèm thông điệp mô tả những việc bạn vừa làm.

git commit -m "feat: login"
💡 Mẹo: Quy tắc Conventional Commits: feat:, fix:, docs:, refactor:
Cơ bản Sửa commit gần nhất

git commit --amend

Sửa lại message của commit gần nhất hoặc gộp thêm các file vừa sửa vào commit trước mà không tạo thêm commit rác mới.

git commit --amend -m "mới"
⚠️ Chú ý: Chỉ dùng khi commit CHƯA được push lên remote chung.
Phân nhánh Quản lý Branch

git branch

Xem danh sách tất cả các nhánh hiện có trong repo nội bộ. Nhánh có dấu * là nhánh bạn đang đứng.

git branch -a
💡 Mẹo: Xóa nhánh đã merge: git branch -d <tên>, ép xóa: -D
Phân nhánh Chuyển đổi nhánh

git switch / checkout

Chuyển không gian làm việc sang một nhánh khác. Lệnh mới khuyên dùng: git switch (rõ ràng hơn lệnh checkout cũ).

git switch -c feature/login
💡 Mẹo: -c (hoặc -b) giúp tạo nhánh mới và lập tức nhảy sang nhánh đó.
Hợp nhất Gộp tính năng

git merge

Hợp nhất các commit từ nhánh chỉ định vào nhánh hiện tại mà bạn đang đứng (thường là merge nhánh tính năng vào main hoặc develop).

git merge feature/login
💡 Mẹo: Luôn git pull nhánh đích trước khi thực hiện merge để giảm thiểu xung đột.
Hợp nhất Làm sạch lịch sử

git rebase

Đặt các commit của nhánh hiện tại lên trên đỉnh của một nhánh khác, tạo lịch sử commit thẳng hàng, đẹp và không sinh ra commit merge thừa.

git rebase main
⚠️ Vàng ngọc: Tuyệt đối KHÔNG rebase trên các nhánh public/chung (như main, dev).
Remote Quản lý kết nối

git remote

Xem và cấu hình liên kết giữa kho lưu trữ trên máy với các kho chứa từ xa (remote) trên GitHub, GitLab, Bitbucket.

git remote -v
💡 Thêm remote: git remote add origin <url>
Remote Đẩy lên Server ⭐

git push

Đẩy toàn bộ commit từ nhánh cục bộ lên nhánh tương ứng trên remote repository (GitHub).

git push -u origin <branch>
💡 Mẹo: Tham số -u (upstream) chỉ cần dùng lần đầu. Các lần sau chỉ cần gõ git push.
Remote Đồng bộ về máy ⭐

git pull

Kéo các commit mới nhất do đồng nghiệp đẩy lên remote về máy bạn và tự động gộp (merge) thẳng vào nhánh bạn đang đứng.

git pull origin main
💡 Bản chất: git pull tương đương với chạy git fetch rồi tiếp tục git merge.
Remote Tải an toàn

git fetch

Tải toàn bộ thông tin các commit và branch mới trên remote về máy nhưng CHƯA gộp vào code đang viết, giúp bạn kiểm tra trước khi quyết định merge.

git fetch origin
💡 Mẹo: Dùng git fetch -p (prune) để tự động dọn dẹp các nhánh đã bị xóa trên GitHub.
Hoàn tác Cực kỳ hữu ích ⭐

git restore

Khôi phục lại nội dung file về trạng thái trước đó. Có thể dùng để hủy chỉnh sửa ở Working Directory hoặc đưa file ra khỏi Staging Area.

git restore --staged <file>
💡 Hủy sửa file: git restore filename (sẽ bỏ mọi thay đổi chưa staged).
Hoàn tác Quay lại quá khứ

git reset

Di chuyển HEAD về một commit trước đó. Có 3 chế độ: --soft (giữ code đã staged), --mixed (giữ code nhưng unstaged), --hard (xóa sạch mọi sửa đổi).

git reset --soft HEAD~1
⚠️ Cảnh báo: --hard làm mất code vĩnh viễn nếu chưa commit vào Git!
Hoàn tác An toàn cho Team

git revert

Tạo một commit MỚI có nội dung đảo ngược lại hoàn toàn so với commit được chỉ định. Không viết lại lịch sử, an toàn khi nhánh đã push lên GitHub.

git revert <commit-hash>
💡 Mẹo: Dùng git revert HEAD để đảo ngược commit vừa tạo ngay lập tức.
Lưu tạm Cứu tinh dở việc

git stash

Cất toàn bộ các đoạn mã đang viết dở vào một ngăn kéo bí mật để trả về working directory sạch sẽ (giúp bạn chuyển nhánh fix bug khẩn cấp).

git stash push -m "wip"
💡 Lấy lại code: git stash pop (lấy ra và xóa khỏi ngăn kéo).
Điều tra Xem lịch sử

git log

Xem lại toàn bộ lịch sử các commit đã thực hiện: mã băm SHA, tác giả, thời gian tạo và thông điệp commit.

git log --oneline --graph
💡 Lệnh VIP: git log --oneline --graph --all hiển thị cây nhánh siêu đẹp.
Điều tra So sánh khác biệt

git diff

Hiển thị chính xác từng dòng code đã được thêm (+) hoặc bớt (-) giữa file đang sửa và phiên bản lưu trong Git.

git diff --staged
💡 Mẹo: Dùng --staged để soi những gì bạn chuẩn bị commit.
Cứu mạng Phao cứu sinh ⭐⭐⭐

git reflog

Nhật ký theo dõi mọi bước di chuyển của con trỏ HEAD. Ngay cả khi bạn lỡ xóa nhánh hay reset hard mất commit, reflog vẫn lưu lại hash để khôi phục!

git reflog
💡 Hồi sinh code: Sau khi tìm thấy SHA, gõ git reset --hard HEAD@{n}.
Nâng cao Bốc commit

git cherry-pick

Chọn duy nhất một commit cụ thể từ nhánh khác và áp dụng vào nhánh hiện tại mà không cần phải merge toàn bộ cả nhánh đó.

git cherry-pick <commit-hash>
💡 Ứng dụng: Bốc một bản vá hotfix vừa commit ở dev đưa gấp vào nhánh release.
Nâng cao Phiên bản Release

git tag

Đánh dấu mốc phiên bản phát hành sản phẩm (ví dụ: v1.0.0, v2.1.0) để tiện theo dõi các đợt release và triển khai production.

git tag -a v1.0.0 -m "Release"
💡 Đẩy tag: Chạy git push origin --tags để đẩy tag lên GitHub.

Không tìm thấy câu lệnh phù hợp

Hãy thử tìm từ khóa khác (ví dụ: commit, branch, merge, reset, stash...)

🚨 Tình Huống Cấp Cứu

Xử Lý Các Lỗi Hay Gặp Khi Làm Việc Nhóm

Bí kíp gỡ rối từng bước nhanh chóng, an toàn và không mất dữ liệu

⚠️ Tình huống 1: Lỡ gõ sai thông điệp commit vừa rồi

Bạn vừa gõ git commit -m "conmit loi" và muốn đổi lại tên chuẩn mà không muốn sinh thêm 1 commit sửa lỗi vô nghĩa.

git commit --amend -m "feat: tên commit chuẩn"
⚠️ Tình huống 2: Đang code dở thì sếp bắt chuyển nhánh fix bug

Nếu chuyển nhánh ngay sẽ bị báo lỗi do có file chưa commit. Hãy cất vào stash rồi sau đó lấy ra lại.

git stash && git switch hotfix && ... && git stash pop
⚠️ Tình huống 3: Xử lý Merge Conflict (Xung đột mã nguồn)

Khi hai người cùng sửa một dòng code, Git sẽ chèn các đánh dấu <<<<<<< HEAD, ======= và >>>>>>>.

1. Mở file xung đột, chọn giữ đoạn code chính xác.
2. Lưu file lại và chạy git add <file>.
3. Hoàn tất bằng lệnh git commit -m "fix: resolve conflict".
⚠️ Tình huống 4: Lỡ chạy git reset --hard làm mất code

Đừng hoảng loạn! Git luôn lưu dấu vết mọi hành động trong nhật ký ẩn reflog. Bạn có thể quay ngược thời gian:

git reflog → git reset --hard HEAD@{1}
